Resumen

De qué trató la reunión

El equipo visitante (Fernando, Sergio, Marco y colegas) se reunió con Karina Jiménez, modeladora de datos / DBA del área de Estudios Económicos, para entender el modelo de datos actual de las encuestas económicas (EMU / MUI, precios, sector privado no financiero), la diferencia entre tablas corporativas y tablas propias de cada negocio, y el proceso formal que el banco exige para crear tablas, esquemas o aplicaciones nuevas.

Detalle

Temas tratados

Modelo de datos y propiedad (ownership)

  • El modelo MUI tiene hoy un solo owner; se busca que soporte varios owners.
  • Existen tablas corporativas compartidas entre sistemas (instituciones, calendario) frente a tablas propias de cada negocio (p. ej. EPR — índice de precio referencial, con submodelos EMU, MST, OVOC, CICO).
  • Lo que el equipo visitante puede ver hoy es solo un visor (Viewer) de solo lectura: no permite crear ni editar tablas directamente.

Sistema de encuestas

  • Hoy la validación de cada cuestionario vive en lógica de cliente (PowerBuilder) por script; cada regla nueva exige programar de cero.
  • Ya hubo un intento previo de validador genérico (con operadores tipo numerador/denominador y dependencias entre preguntas) que no se terminó de implementar.
  • Objetivo del equipo visitante: que el cliente genere un JSON con el esquema del cuestionario, el backend lo valide y arme un esquema dinámico persistido en base de datos — hoy esas reglas solo existen en scripts, no son consultables.
  • Jerarquía de negocio confirmada: Encuesta → Cuestionarios → Secciones → Preguntas, cada cuestionario con sus propias reglas y dependencias.

Estándares y proceso de solicitud

  • Toda tabla o aplicación nueva pasa por Ingeniería de Procesos (DIP) y se canaliza como ticket a través del DAU (Departamento de Atención al Usuario, ext. 8777).
  • Karina administra los códigos de aplicación (4 letras) y la tabla maestra de aplicaciones del banco.
  • Existe una plantilla Excel — "solicitud de requerimientos para modelado de datos" — donde se documentan tablas, campos, tipo de clave y restricciones; es la entrada estándar para que Karina modele.
  • Los nombres de tabla y campo están limitados a 18 caracteres (30 para referencias y secuencias), de ahí nacen abreviaciones poco intuitivas como pregunta_cuest.
  • Las claves compuestas son el estándar histórico en Estudios Económicos desde los años 90 (integridad de datos); otras áreas del banco sí usan IDs autogenerados. Karina recomienda mantener claves compuestas dado el volumen de registros.

Acceso a herramientas

  • Power Designer requiere licencia atada a una máquina específica; el equipo visitante aún no tiene equipos asignados ni licencia.
  • El acceso al modelo/visor debe solicitarse al jefe de área (Alexander/Ángel).

Logística

  • La planta eléctrica de respaldo solo cubre hasta el piso 12 — riesgo a validar antes de subir a pisos superiores.
